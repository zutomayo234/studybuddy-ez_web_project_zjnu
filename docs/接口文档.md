# StudyBuddy 接口文档

- 基础地址：`http://localhost:8080`
- 数据格式：`application/json`
- 统一响应结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1759888888888
}
```

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录 / 令牌过期 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 409 | 资源冲突（如用户名重复、移除最后一个管理员） |
| 422 | 触发提示注入拦截 |
| 500 | 服务器内部错误 |

鉴权方式：除公开接口外，请求头需携带 `Authorization: Bearer <token>`。

> **文档来源说明（功能增强后新增）**
>
> 自功能增强起，接口契约的**唯一权威来源**改为后端运行时生成的 OpenAPI 文档：
>
> - Swagger UI：<http://localhost:8080/swagger-ui/index.html>
> - OpenAPI JSON：<http://localhost:8080/v3/api-docs>
>
> 本文档保留为便于离线阅读的手写版本，内容仍与代码保持一致，但**若两者出现分歧，以 OpenAPI 文档为准**。手写文档与代码脱节正是增强阶段引入 springdoc 的原因。

## 1. 连通性测试

**GET** `/api/hello`　公开

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "app": "studybuddy",
    "message": "Hello, 学习搭子 StudyBuddy!",
    "time": "2026-10-08T09:54:11.123"
  }
}
```

## 2. 认证

### 2.1 登录

**POST** `/api/auth/login`　公开

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码（明文传输需 HTTPS，服务端 BCrypt 校验） |

```json
{ "username": "admin", "password": "admin123" }
```

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "roles": ["ROLE_ADMIN"],
  "permissions": ["user:list", "user:create", "user:update", "user:delete", "ai:chat",
                  "role:list", "role:assign", "kb:manage", "log:list", "stats:view"],
  "user": {
    "id": 1, "username": "admin", "nickname": "系统管理员",
    "phone": "138****0001", "genderText": "男", "status": 1,
    "roleCodes": ["ROLE_ADMIN"]
  }
}
```

> 登录成功后返回的 `roles` 与 `permissions` 会被前端保存，用于渲染菜单与拦截路由（前端侧的权限判断只是体验优化，真正的权限边界仍在后端 `@PreAuthorize`）。

### 2.2 注册

**POST** `/api/auth/register`　公开

请求体同"新增用户"（见 3.3）。

### 2.3 当前登录用户

**GET** `/api/auth/me`　需登录

`data`：

```json
{
  "user": { "id": 1, "username": "admin", "nickname": "系统管理员", "roleCodes": ["ROLE_ADMIN"] },
  "roles": ["ROLE_ADMIN"],
  "permissions": ["user:list", "user:create", "..."]
}
```

### 2.4 修改本人密码

**PUT** `/api/auth/password`　需登录

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| oldPassword | string | 是 | 旧密码，**必须校验** |
| newPassword | string | 是 | 新密码，≥6 位，且不得与旧密码相同 |

```json
{ "oldPassword": "admin123", "newPassword": "admin456" }
```

错误码：旧密码错误 → `400`；新旧密码相同 → `400`。

> 与 3.6 的"管理员重置密码"是两个不同的接口：前者需校验旧密码（证明是本人），后者属管理行为、需要 `user:update` 权限。

## 3. 用户管理（RESTful）

> 权限列基于 RBAC：`ROLE_ADMIN` 拥有全部权限；教师拥有 `user:list`（无增删改）；学生无用户接口权限。完整的权限划分见实验四报告。

### 3.1 分页查询

**GET** `/api/users`　权限：`user:list`

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| keyword | string | 否 | — | 匹配用户名 / 昵称 / 邮箱 |
| status | int | 否 | — | 1 正常 0 禁用 |
| pageNum | int | 否 | 1 | 页码 |
| pageSize | int | 否 | 10 | 每页条数 |

`data`：

```json
{
  "pageNum": 1, "pageSize": 10, "total": 3, "pages": 1,
  "list": [
    { "id": 1, "username": "admin", "nickname": "系统管理员",
      "email": "admin@zjnu.edu.cn", "phone": "138****0001",
      "genderText": "男", "status": 1, "roleCodes": ["ROLE_ADMIN"],
      "createTime": "2026-10-08 09:54:11" }
  ]
}
```

### 3.2 查询详情

**GET** `/api/users/{id}`　权限：`user:list`

### 3.3 新增

**POST** `/api/users`　权限：`user:create`

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | 3~20 位，唯一 |
| password | string | 是 | 6~32 位，服务端 BCrypt 加密后入库 |
| nickname | string | 否 | ≤20 位 |
| email | string | 否 | 邮箱格式 |
| phone | string | 否 | `1[3-9]\d{9}` |
| gender | int | 否 | 0/1/2，默认 0 |
| status | int | 否 | 默认 1 |
| remark | string | 否 | 备注 |

### 3.4 更新

**PUT** `/api/users/{id}`　权限：`user:update`

可更新 `nickname / email / phone / gender / status / remark`；用户名与密码不在此接口修改。

### 3.5 删除（逻辑删除）

**DELETE** `/api/users/{id}`　权限：`user:delete`

### 3.6 重置密码（管理员）

**PUT** `/api/users/{id}/password?password=新密码`　权限：`user:update`

### 3.7 分配角色（功能增强）

**PUT** `/api/users/{id}/roles`　权限：`role:assign`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| roleIds | number[] | 是 | 全量覆盖该用户的角色；不得为空数组 |

```json
{ "roleIds": [2, 3] }
```

错误码：`roleIds` 为空 → `400`；含不存在的角色 ID → `400`；**移除系统中最后一个管理员的管理员角色 → `409`**。

## 4. 智能问答（实验五）

**POST** `/api/ai/chat`　权限：`ai:chat`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| question | string | 是 | 问题，≤2000 字 |
| useRag | boolean | 否 | 是否启用检索增强，默认 true |
| sessionId | number | 否 | 会话 ID；不传则新建会话（功能增强后支持多轮） |

```json
{ "question": "密码能不能明文存库？", "useRag": true, "sessionId": 3 }
```

响应 `data`：

```json
{
  "answer": "密码绝对不能明文存库……（基于资料的作答）",
  "references": ["第11条：密码绝对不能明文存库，必须使用不可逆的哈希算法……"],
  "model": "deepseek-flash",
  "fallback": false,
  "sessionId": 3,
  "contextSize": 2
}
```

| 字段 | 说明 |
| --- | --- |
| sessionId | 本次问答所属会话；首次调用时由后端新建并返回 |
| contextSize | 本次实际回灌的历史消息条数（多轮对话时大于 0） |

错误码：

- `422`：命中提示注入黑名单（如"忽略之前的指令"），返回拦截提示；
- `400`：问题超长。

### 4.1 我的会话列表（功能增强）

**GET** `/api/ai/sessions`　权限：`ai:chat`　→ 返回当前用户的会话（含标题、更新时间、消息数）。

### 4.2 某会话的消息历史（功能增强）

**GET** `/api/ai/sessions/{id}/messages`　权限：`ai:chat`

- 会话不属于当前用户 → `404`（归属校验写在 SQL 中）。
- 返回该会话全部消息（按时间正序，含 role、content、refExcerpt、fallback、createTime）。

### 4.3 删除会话（功能增强）

**DELETE** `/api/ai/sessions/{id}`　权限：`ai:chat`　→ 删除会话及其消息。

## 5. 角色与权限（功能增强）

**GET** `/api/roles`　权限：`role:list`　→ 角色列表，含每个角色的权限明细与人数。

**GET** `/api/roles/permissions`　权限：`role:list`　→ 权限点全集（前端勾选树的候选）。

**PUT** `/api/roles/{id}/permissions`　权限：`role:assign`

```json
{ "permIds": [1, 5] }
```

以**全量覆盖**方式更新该角色的权限；权限 ID 不存在 → `400`。

## 6. 知识库（功能增强）

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/kb/chunks` | `kb:manage` | 查看知识库全部片段 |
| GET | `/api/kb/stats` | `kb:manage` | 片段总数、运行时片段数、来源文件、topK |
| POST | `/api/kb/reload` | `kb:manage` | 重新加载知识库（保留运行时追加的片段） |
| POST | `/api/kb/chunks` | `kb:manage` | 追加一个片段 |

追加片段请求体：

```json
{ "text": "接口幂等性：同一请求重复执行多次，对系统状态的影响与执行一次相同。" }
```

> 后两个写操作带 `@OpLog`，会在操作日志中留痕。

## 7. 操作日志（功能增强）

**GET** `/api/logs`　权限：`log:list`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| module | string | 否 | 按业务模块筛选 |
| username | string | 否 | 按操作人筛选 |
| success | int | 否 | 1 成功 / 0 失败 |
| pageNum / pageSize | int | 否 | 分页，默认 1 / 10 |

> 日志由 AOP 切面在带 `@OpLog` 的方法执行后自动写入；**被 `@PreAuthorize` 拒绝的请求同样会留痕（success=0）**。

## 9. curl 调用示例

```bash
# 1) 连通性
curl http://localhost:8080/api/hello

# 2) 登录拿 token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}"

# 3) 带 token 查询用户列表
curl "http://localhost:8080/api/users?pageNum=1&pageSize=10" \
  -H "Authorization: Bearer <你的token>"

# 4) 新增用户
curl -X POST http://localhost:8080/api/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"username\":\"test01\",\"password\":\"123456\",\"nickname\":\"测试用户\",\"email\":\"test01@zjnu.edu.cn\"}"

# 5) 智能问答
curl -X POST http://localhost:8080/api/ai/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"question\":\"前后端分离跨域怎么解决？\",\"useRag\":true}"

# 6) 多轮追问（带上一次返回的 sessionId）
curl -X POST http://localhost:8080/api/ai/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"question\":\"那它和 JWT 有什么区别？\",\"sessionId\":3}"

# 7) 修改本人密码
curl -X PUT http://localhost:8080/api/auth/password \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"oldPassword\":\"admin123\",\"newPassword\":\"admin456\"}"

# 8) 查看角色列表（含权限明细与人数）
curl http://localhost:8080/api/roles -H "Authorization: Bearer <你的token>"

# 9) 给用户分配角色
curl -X PUT http://localhost:8080/api/users/3/roles \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"roleIds\":[2,3]}"

# 10) 知识库：追加片段 + 重新加载
curl -X POST http://localhost:8080/api/kb/chunks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的token>" \
  -d "{\"text\":\"接口幂等性：同一请求重复执行多次，对系统状态的影响与执行一次相同。\"}"

curl -X POST http://localhost:8080/api/kb/reload -H "Authorization: Bearer <你的token>"

# 11) 查询操作日志 / 数据看板
curl "http://localhost:8080/api/logs?pageNum=1&pageSize=10" -H "Authorization: Bearer <你的token>"
curl http://localhost:8080/api/stats/overview -H "Authorization: Bearer <你的token>"
```
